# 29.13 — Semantic Preservation

> *Preservar a **semântica** de uma arquitetura, não apenas executar seus binários.*
> Extensão do Path v1.9 sobre o pipeline v1.7/v1.8 (`x86 → SIR → multi-ISA`).

Preservation Layer formalizado em `base-vault/isa/` (níveis P0–P5, matriz + snapshots
gerados por `base recomp report`).

## Três níveis de confiança

| Nível | Pergunta | Mecanismo |
|-------|----------|-----------|
| **literal** | os mesmos bytes recuperam a mesma forma? | `decode(encode(SIR)) == SIR` |
| **semantic** | a forma recuperada tem o mesmo significado? | `semantic_key(SIR) == semantic_key(SIR′)` (domínio 32-bit) |
| **differential** | produz o mesmo estado arquitetural? | `execute_reference(SIR, state, width, endian) == execute_isa(decode(encode(SIR)), state)` |

Palavra não reconhecida → `Op::Unknown` (gap), nunca mis-decode silencioso.

## Componentes (`base-recomp`)

| Módulo | Papel |
|--------|-------|
| `semantics.rs` | Catálogo serde das 11 ISAs (regs, endianness, delay slots, flags, ABI, quirks, status de encode) |
| `decode.rs` | Decoders subset (MIPS/PPC/SuperH/Alpha/PA-RISC/ColdFire/ARM/AArch64/SPARC/x86_64) que invertem os encoders |
| `verify.rs` | Round-trip + `semantic_key` + cobertura por dimensão + `differential_kind` |
| `semexec.rs` | Execução de referência: `MachineState { gpr, pc, flags, mem }`, `load`/`store`, push/pop, `differential_sweep` |

## Bugs reais que o verifier encontrou

1. **PPC `r0`**: lê como 0 no campo RA de `addi` → `MovImm{r0}` e `AddImm{r0}` colidiam. Fix: VReg → `r3..r31`.
2. **ColdFire `Dn`**: bits 5-3 sem `<< 3` no grupo `addi/subi/clr/addq/subq/push` → `clr.l d3` virava `clr.l (a3)+`. Só D0 passava no roundtrip antigo (VReg 0).
3. **Alpha "sign-extension"** (revelado pelo diferencial): o encoder LDA sign-extendia o
   disp corretamente, mas o executor de referência tratava imeds SIR como `u32` quando o
   domínio do SIR é `i32` (`AddImm{0xFFFFFFFF}` ≡ `Dec`). Fix em `semexec::execute`
   (sign-extend i32 → largura): differential Alpha 50% → 57% (14 kinds), sweep 176/176.
4. **ColdFire push/pop bug** (revelado ao adicionar load/store): encoder antigo `0x29C0` =
   `move.l d0,(a4)+` (não era push!) e campo Dn em bits errados — o sweep só usava VReg 0
   (D0), roundtrip consistente-mas-errado. Validação capstone m68k corrigiu: push
   `0x2F00|dn` (Dn em bits 2-0), pop `0x201F|dn<<9`. LD/ST novos: `move.l (An),Dn` /
   `move.l Dn,(An)`, todos capstone-verificados.

`abi/privileged/mmu/system` = `0%` (não modelados). Sweep gerado: coldfire 268/268,
x86_64 268/268, mips/ppc/alpha 184/184, aarch64 144/144, arm 112/112, sparc 64/64 —
**todas as ISAs com decoder têm sweep limpo**. **Load/store no SIR** (`LdMem`/`StMem`):
executor referencia endianness do ISA; encoders/decoders em **9 ISAs** — ColdFire
(`move.l (An),Dn`), MIPS (`lw/sw`), PPC (`lwz/stw`), Alpha (`ldq/stq` width 8), AArch64

`8B/89` [base]→eax) — **todos capstone-verificados** (Alpha contra seu formato de
memória, padrão LLVM). Probes usam `word_bits/8`. ColdFire e x86_64 = 86% em todas
dimensões; MIPS/PPC/Alpha/AArch64/ARM = 71%; SPARC 43%.
